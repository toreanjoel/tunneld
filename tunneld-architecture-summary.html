tunneld

An ethernet-first private network edge relay for ARM single-board computers. The gateway owns the LAN; a fleet manager provisions Incus containers and VMs over SSH on machines it reaches locally or remotely — all from one LiveView dashboard.

1Overview & topology

Tunneld is software installed on a dual-NIC ARM64 single-board computer that turns it into a wired edge gateway for a private subnet, plus a fleet manager for Incus containers and VMs running on machines it reaches over SSH. Two capabilities, one relationship: the gateway owns the network, and the instances it manages live on or are reachable from that network.

Built on Elixir/Phoenix LiveView and the BEAM. No database — all state is atomic JSON files under a configurable data root.

WAN (upstream) ── Tunneld SBC ── LAN (downstream) ── switch ── devices
                        │
                        └── SSH ──> targets (local machines / remote VMs)
                                       └── Incus ──> containers & VMs

No Wi-Fi. No overlay network. No control-plane dependency.

2Gateway responsibilities

  • DHCP + DNS via dnsmasq on the LAN interface; user-configurable upstream DNS servers (Cloudflare, Pi-hole, or your own resolver).
  • Lease/device visibility — every device on the subnet is listed with hostname, MAC, and IP.
  • NAT / forwarding / DNS interception via iptables on the upstream↔downstream pair.
  • Named resolution — dnsmasq resolves any *.tunneld.lan name to the gateway, so named resources and exposed services are reachable by name across the subnet.
  • Service monitoring of the underlying systemd units (dnsmasq, dhcpcd, nginx).
  • Auth — sessions, bcrypt + WebAuthn.
  • Works offline — local networking, DHCP, and name resolution keep functioning without internet.

3Fleet management (Machines + Incus)

  • Machines are targets tunneld manages. tunneld generates an Ed25519 keypair per machine and shows the public half to install on the target; it then probes capabilities over SSH and can provision Incus containers/VMs.
  • Targets may be local (on the gateway's subnet) or remote (a VM/VPS with a public address). The location field is inferred from the subnet and drives the networking model for containers.
  • Targets must present a Linux SSH endpoint. Non-Linux hosts are managed via a Linux VM on that host; tunneld talks to the VM, not the physical machine.
  • Once provisioned, tunneld can create, start, stop, list, and delete Incus instances, and open an interactive shell into a container over the browser.
  • State is queried live over SSH (incus list, incus info) rather than persisted and reconciled. The target is the source of truth; tunneld persists only the target list and credentials.
  • Host specs (CPU, memory, storage, architecture, KVM, GPU) are surfaced per target from a capability probe.

4Container networking (macvlan vs bridge)

  • Local targets → macvlan: a macvlan container gets its own MAC address and DHCP lease straight from the gateway's dnsmasq, appearing on the subnet as an independent device. It is reachable by name and SSH-able with no proxying.
  • Remote targets → NAT bridge: the container is behind the remote host. Reaching an app inside it requires an explicit exposure path (see below).

5Exposing remote container services

macvlan only spans a single Layer-2 segment, so a container on a remote machine cannot appear as a subnet device. For remote targets, tunneld instead:

  • Opens a reverse SSH port-forward (ssh -L) from the gateway to the container's port on the remote host, and
  • Registers an nginx resource pointing at the forwarded port.

The container service becomes reachable subnet-wide at http://<name>.tunneld.lan:18000, indistinguishable from a local service. Exposures are persisted in expose.json and the tunnels are re-opened automatically on gateway startup so they survive reboots.

6Resources & reverse proxy

  • nginx runs on the gateway and fronts a resource registry (resources.json). Each resource has a name and a pool of IP:port backends, health-checked via TCP probes every 10 seconds.
  • nginx load-balances across healthy backends; each resource is reachable at http://<name>.tunneld.lan:18000. No public-internet exposure, no per-resource auth — access is limited to the subnet.
  • A resource is a named pointer to already-running backends. For containers, local macvlan and remote expose handle this automatically; Add Resource is mainly for non-container services running directly on devices.

7Device-facing API & Quick Expose

  • Quick Expose: a subnet device can create/list/remove a local resource with a single curl. The gateway resolves the caller from its DHCP lease and validates a per-device allowlist.
  • Device read API (no-login, gated by DHCP lease): any device can query machines, containers, resources, and gateway health, e.g. GET /api/v1/device/machines.

8Supervision tree & persistence

One one_for_one supervisor (Tunneld.Supervisor) starts Telemetry, DNSCluster, PubSub, the Endpoint, and the domain servers: Session, SystemResources, Services, Resources, Devices, Auth, DnsConfig, Updater, Machines, Expose, and Geolocation. In mock mode a fake Incus/SSH target is also started.

Persistent state (atomic temp-file + rename, with .bak recovery):

FilePurpose
auth.jsonbcrypt admin credentials + onboarding flag
resources.jsonResource registry (name, pool, kind)
machines.jsonEnrolled machines (id, name, address, ssh_port, kind, location, capabilities)
expose.jsonActive remote container exposures (tunnel + resource records)
dns.jsonUpstream DNS server IP

Machine SSH private keys are stored per-machine under the data root's ssh/ directory (mode 0600).

11Explicitly out of scope

  • Wi-Fi bridging and all wireless management.
  • zrok / OpenZiti integration and public/private shares.
  • WireGuard mesh, relay coordinator, and per-peer key exchange.
  • Local PKI and per-resource certificate issuance.
  • Automatic nginx config generation beyond the resource pool model.
  • CLI quick-share beyond the device-facing API.
  • Off-LAN / internet exposure of resources — operator-managed, separate from tunneld.
