07 — DNS, dnsmasq & DHCP

Key source: lib/tunneld/iptables.ex, lib/tunneld/servers/dns_config.ex, lib/tunneld/servers/devices.ex

What DNS and DHCP Are

DNS (Domain Name System) translates human-readable names like google.com into IP addresses like 142.250.80.46. Without DNS, you would need to memorize IP addresses for every website. DNS is hierarchical: your device asks a resolver, which asks root servers, which delegate to TLD servers, which delegate to authoritative servers.

DHCP (Dynamic Host Configuration Protocol) automatically assigns IP addresses to devices when they join a network. Without DHCP, you would manually configure each device with an IP, subnet mask, gateway, and DNS server. DHCP also assigns the default gateway (option 3) and DNS servers (option 6).

dnsmasq is a lightweight program that provides both DNS forwarding and DHCP serving in one process. It is perfect for small networks: it caches DNS responses (speeding up repeated queries), serves local /etc/hosts entries, and can resolve custom domains. Tunneld uses dnsmasq to resolve *.tunneld.lan names and to assign IPs to devices on the subnet.

How DNS Works

DNS Record Types

DNS stores different types of records:

  • A — maps a name to an IPv4 address (example.com → 93.184.216.34)
  • AAAA — maps a name to an IPv6 address
  • CNAME — alias to another name (www.example.com → example.com)
  • MX — mail server for a domain
  • TXT — arbitrary text (used for verification, SPF, etc.)
  • NS — authoritative nameserver for a zone
# Query an A record:
$ dig +short example.com A
93.184.216.34

# Query a specific nameserver:
$ dig @8.8.8.8 example.com A

# Full query with all sections:
$ dig example.com

How DHCP Works (DORA)

DHCP uses a four-step handshake called DORA:

  1. Discover — client broadcasts "I need an IP" (UDP, src 0.0.0.0)
  2. Offer — server responds "Here's 10.0.0.50, want it?"
  3. Request — client broadcasts "Yes, I want 10.0.0.50"
  4. Acknowledge — server confirms "It's yours for N seconds"

The ACK includes options: subnet mask, default gateway (option 3), DNS servers (option 6), lease time, and more. When the lease expires, the client must renew or get a new address. 

# DHCP options in the ACK:
Option 1  (Subnet Mask):     255.255.255.0
Option 3  (Router):          10.0.0.1       <-- This makes Tunneld the gateway
Option 6  (DNS Server):      10.0.0.1
Option 51 (Lease Time):      86400 seconds

How Tunneld Uses DNS and DHCP

dnsmasq Configuration

dnsmasq is installed and configured by the Tunneld installer. It listens on the downstream interface and serves DHCP for the 10.0.0.0/24 range. It also resolves *.tunneld.lan to the gateway IP, enabling name-based access to resources.

The installer writes /etc/dnsmasq.conf with settings like: 

# /etc/dnsmasq.conf (set by installer):
interface=eth1                        # Listen on downstream only
dhcp-range=10.0.0.100,10.0.0.250,12h  # DHCP pool
dhcp-option=3,10.0.0.1                # Option 3: Tunneld is the gateway
dhcp-option=6,10.0.0.1                # Option 6: Tunneld is DNS server
address=/tunneld.lan/10.0.0.1         # *.tunneld.lan -> gateway
port=5336                             # Listen on 5336 (iptables redirects 53)

DNS Interception

Even if a device has hardcoded DNS (like 8.8.8.8), Tunneld intercepts it. iptables redirects all port 53 traffic to dnsmasq on port 5336. This ensures consistent name resolution for *.tunneld.lan regardless of device configuration. 

# From lib/tunneld/iptables.ex:
defp dns_forwarding() do
  System.cmd("iptables", [
    "-t", "nat", "-A", "PREROUTING",
    "-p", "udp", "--dport", "53",
    "-j", "REDIRECT", "--to-port", "5336"
  ])
end

Upstream DNS Selection

Users can choose their upstream DNS server from the dashboard. This is stored in dns.json and used by dnsmasq for forwarding non-local queries. 

# From lib/tunneld/servers/dns_config.ex:
def set_dns_server(ip) do
  write_dns(%{"server" => ip})

  # Update iptables exemptions
  Tunneld.Iptables.set_dns_server(ip)

  # Reload dnsmasq
  System.cmd("systemctl", ["restart", "dnsmasq"])

  broadcast(:dns_update)
end

Lease Monitoring

lib/tunneld/servers/devices.ex reads the DHCP lease file (/var/lib/misc/dnsmasq.leases) every 10 seconds to show connected devices in the dashboard. The fetch_devices/0 function reads and parses the file: 

# Lease file format:
# expire_timestamp MAC_address IP hostname client_id
1723456789 aa:bb:cc:dd:ee:ff 10.0.0.100 my-laptop *

# From lib/tunneld/servers/devices.ex:
def fetch_devices() do
  {data, _} =
    if mock?() do
      Tunneld.Servers.FakeData.devices()
    else
      case File.read(@path) do
        {:ok, content} -> {content, 0}
        {:error, _} -> {"", 1}
      end
    end

  leases =
    if String.trim(data) == "", do: [], else: String.split(String.trim(data), "\n")

  Enum.map(leases, fn lease ->
    [lease_expiry, mac, ip, hostname, client_id] = String.split(lease, " ")

    %{
      expiry: lease_expiry,
      mac: mac,
      ip: ip,
      hostname: hostname,
      client_id: client_id,
      type: ""
    }
  end)
end

Why dnsmasq

Combined DNS and DHCP

Running separate DNS (bind) and DHCP (isc-dhcp-server) services would be more complex. dnsmasq does both in one lightweight process, ideal for an SBC with limited resources.

Easy Local Domains

The address=/tunneld.lan/10.0.0.1 directive makes all *.tunneld.lan names resolve to the gateway. No zone files, no record management — just one line.

DNS Interception

Devices with hardcoded DNS (IoT devices, corporate laptops) would bypass local names. Intercepting all DNS ensures resource.tunneld.lan always works, even on stubborn devices.

Examples

View DHCP leases

$ cat /var/lib/misc/dnsmasq.leases
1723456789 aa:bb:cc:dd:ee:ff 10.0.0.100 my-laptop *
1723456790 11:22:33:44:55:66 10.0.0.101 raspberry-pi 01:11:22:33:44:55:66

Test DNS resolution

# From a device on the subnet:
$ dig @10.0.0.1 ollama.tunneld.lan +short
10.0.0.1

$ dig @10.0.0.1 google.com +short
142.250.80.46

# Test that interception works (even querying 8.8.8.8):
$ dig @8.8.8.8 ollama.tunneld.lan +short
10.0.0.1  # Still resolves because iptables redirected to dnsmasq

Restart dnsmasq

$ sudo systemctl restart dnsmasq
